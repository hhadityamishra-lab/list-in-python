OOP Concepts Used — Simply Explained

1. Abstract Class (Coffee)

Think of it as a promise/blueprint. You cannot make a generic "Coffee" object — you must make a specific one (Latte, Espresso, etc.). Every child class is forced to define get_name(), get_recipe(), and art().

python
class Coffee(ABC):
    @abstractmethod
    def get_name(self): pass

2. Inheritance

Every coffee type inherits from Coffee, which means it automatically gets the serve() method for free — no need to rewrite it.

python
class Latte(Coffee):   # Latte IS-A Coffee ✅

3. Encapsulation

Ingredients are stored as private (__ingredients) inside each class. Outside code can't directly touch them — only get_recipe() allows access. This is like a locked recipe book that only serves what it wants to show.

python
self.__ingredients = ["1 shot Espresso", ...]  # Private!
